# 🤖 GitHub Copilot Prompt Playbook for Laravel 12 ERP Project

This playbook defines how GitHub Copilot should generate, extend, or refactor code for this ERP system.

---

## 🧱 Stack

- Laravel 12 (REST API + FormRequest + Service Architecture)
- Inertia.js + React (SPA frontend)
- Tailwind CSS + shadcn/ui components
- Sanctum for API authentication
- spatie/laravel-permission for roles and capabilities
- GitHub Copilot for assisted development

---

## 📂 Project Structure (Modular + Scalable)

- Models → app/Models/{Model}.php  
- Requests → app/Http/Requests/{Feature}/{StoreXRequest, UpdateXRequest}.php  
- Controllers:
  - API → app/Http/Controllers/Api/{Feature}Controller.php
  - Inertia UI → app/Http/Controllers/{Feature}InertiaController.php
- Resources → app/Http/Resources/{Model}Resource.php
- Pages → resources/js/Pages/{Feature}/{Index,Create,Edit}.jsx
- Layouts → resources/js/Layouts/AppLayout.jsx
- Routes:
  - API → routes/api.php
  - Web → routes/web.php
- Migrations → database/migrations/
- Changelog → CHANGELOG.md

---

## 🔁 Model & Relationships

- Models use casts (e.g. boolean, decimal:2)
- Models may include belongsToMany(), hasMany(), etc.
- Pivot tables must be explicitly created when needed
- Every model must follow fillable/cast conventions

---

## 🔐 Authentication & Access

- Laravel Sanctum is used for SPA & API token authentication
- Users may have multiple roles and capabilities (via spatie/laravel-permission)
- Authorization logic may exist in policies, gates, or inline controller checks
- Role names follow WordPress conventions (administrator, editor, etc.)
